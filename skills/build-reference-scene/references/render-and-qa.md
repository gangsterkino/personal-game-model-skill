# 灯光、材质与真实渲染

## 设计
记录目标观感、参考图、相机、尺寸、引擎、设备、采样上限和时间预算。现有工程先保存同镜头基准图。复刻先锁定大形体与构图；美化优先识别最显眼的不足。

## 材质
用真实尺度判断木纹、石材凹凸与布料纹理；粗糙度决定反射层次。颜色贴图与法线/粗糙度等数据图使用对应色彩空间。检查UV拉伸、法线方向、金属通道和丢贴图，不用强光掩盖问题。

## 光照
室内关注窗光路径、天花/墙体遮挡、暖色实际灯源和间接反弹。按主题决定冷暖对比，保留暗部层次；不用大面积填充把所有物件照平。摄影棚、外景、风格化场景分别选择方法，不硬套三点光。

## 渲染
引擎和节点以当前Blender实际API为准。Cycles写实路径与EEVEE实时预览按需求选择；探测实际GPU并记录回退。相机必须有效，避免无意裁切。保留已有合成器，不重复降噪；HDRI、辉光、景深和雾只在有视觉依据时添加。

先小图后最终图，按几何/相机→材质→光照→曝光→后期的原因顺序修复。采样数提高主要解决噪声，不会把错误的模型变真实。查看实际PNG，不把进程退出码当作美术完成标准。

## 交付门槛
检查构图、尺度、接地、穿插、物体轮廓、纹理密度、反射、曝光、噪点和风格统一性；保存前后对照和具体改动。用户指出无明显改善时，重做影响最大的部件，不再只微调全局色温。

在新位置/干净进程重开工程，确认贴图和外部缓存可找到并能渲染。记录实际参数、耗时、近似替代与阻塞。静态图、动画、GLB与引擎实现分别验收，不互相冒充。
